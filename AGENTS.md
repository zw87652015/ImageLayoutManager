# ImageLayoutManager — agent notes

## Environment
- Conda env: `imagelayout` (`conda env create -f environment.yml`); `git` is not on PATH in the default shell.
- Run the app: `python main.py`; headless CLI: `python cli_main.py --help`.
- Canvas tabs use Qt's scrollable QWidget viewport by default; forcing `QOpenGLWidget` on every tab made pan/repaint slower as the viewport grew (Windows 2560×1440 synthetic pan: ~15 ms/frame vs ~4 ms/frame). The default canvas viewport has `WA_OpaquePaintEvent`: `CanvasScene.drawBackground` fills its entire exposed rect, and the opaque hint avoids redundant clearing on each full-viewport middle-button pan (near-fullscreen paint ~4.8 → ~3.8 ms in a Windows synthetic drag). Keep background and page pixels correct after panning/zooming at high DPI. Set `ILM_CANVAS_OPENGL=1` before launch only to opt back into the old backend for comparison. `python -m unittest test_canvas_pan` verifies the default, opt-in, middle-button drag, pixel-wheel pan, and large-viewport painting.
- Windows packaging: keep Qt DLLs under `_internal/PyQt6/Qt6/bin`, not duplicate `_internal/Qt6*.dll` copies from Conda. Inno Setup upgrades must also remove obsolete top-level Qt DLLs with the targeted `[InstallDelete]` rule; copying a clean bundle over an old installation leaves stale DLLs behind. `python -m unittest test_windows_packaging` checks that cleanup stays limited to those files.
- macOS packaging: `build_onefile_macos.py` writes a generated spec (`build/ImageLayoutManager-macos.spec`) with two EXEs (GUI `ImageLayoutManager` + console `imagelayout-cli`) → one COLLECT → one BUNDLE, so both share `Contents/Frameworks`/`Contents/Resources`. The GUI EXE must stay first in the COLLECT — BUNDLE makes it `CFBundleExecutable`. COLLECT inherits `console` from its *last* EXE (the CLI), which makes BUNDLE write `LSBackgroundOnly=true` (no Dock icon/menu bar) and drop `NSHighResolutionCapable`, so the spec's BUNDLE sets both explicitly via `info_plist`; the build fails if the final Info.plist regresses. The CLI lives at `Contents/MacOS/imagelayout-cli`; `mcp_guide_dialog._CLI_NAME` picks the platform suffix. Build with `.venv/bin/python build_onefile_macos.py`. Signing: `--codesign-identity`/`MACOS_CODESIGN_IDENTITY` takes a "Developer ID Application" identity (full name or SHA-1) and passes it to both EXEs so PyInstaller signs all nested code with hardened runtime + timestamp; `--bundle-id` sets CFBundleIdentifier (default `com.zw87652015.imagelayoutmanager`). After the Info.plist/license edits the script re-seals the outer bundle without `--deep` (nested code is already signed) and `_verify_signature` fails the build on any unsigned/ad-hoc nested Mach-O. `--notary-profile`/`MACOS_NOTARY_PROFILE` (a `notarytool store-credentials` keychain profile) additionally notarizes, staples, spctl-checks, and writes `dist/ImageLayoutManager_v<ver>_macOS_<arch>.zip` with its SHA-256; without an identity the result is ad-hoc only.

- The Layers panel (`src/app/layers_panel.py`) has two shapes. In grid mode it groups cells by row/column — a stable structural identity kept across swaps, unrelated to draw order — and cells are *not* draggable: z_index is meaningless while cells can't overlap (the row items carry no drag/drop flags and `MainWindow._on_layers_reorder_requested` ignores stray cell reorders). In freeform mode (`project.layout_mode == 'freeform'`, detected by `refresh()` → `tree.cells_reorderable`) it switches to a Photoshop-style flat layer list that *is* the z-stack: top row = frontmost (sort key `(z_index, creation index)` descending — creation order is the canvas's tie-break for equal zValues), no row headers, and PiP children shown reversed so they read front-to-back like their parents. Drag mechanics are Photoshop-like: the pointer's vertical half inside a row picks the boundary above/below it, `_BranchlessTree.paintEvent` draws an accent insertion line at that boundary (Qt's own drop indicator is disabled), hovering another cell's expanded inset rows maps to "behind that cell", and empty space below the list means the back of the stack. A drop emits `reorder_requested(dragged_id, target_id, place_above)` where place_above means "in front of the target" — never a reparent — for `MainWindow._on_layers_reorder_requested` to turn into `ReorderZIndexCommand` (renumbers every leaf cell's `z_index` to its rank — compact and deterministic, unlike `ZIndexChangeCommand`'s raw ±1 used by Bring to Front/Send to Back, which both remain) or `ReorderPipItemsCommand` (reorders `cell.pip_items`; list order *is* the PiP stack, last = frontmost). Drops that would land the cell on the stack slot it already occupies are skipped so undo history stays clean. PiP insets stay draggable in both modes — they overlap their host cell regardless of layout. A small "Z±n" chip (`_ROLE_ZIDX`) only appears on a grid-mode cell row once its `z_index` differs from the default 0 (in freeform the row's position already *is* its rank, so the chip is suppressed there). Selection invariant (`MainWindow._select_cells_by_ids`, driven by the tree's `items_selected`): picking a PiP row must also Qt-select its parent `CellItem` and deselect PiPs on every other cell, and picking any cell must clear every `_selected_pip_id` — otherwise the stale id keeps routing `_on_selection_changed` to the PiP inspector branch after the user returns to the cell. Both paths run under a `QSignalBlocker` on the scene with a single `_on_selection_changed()` afterwards. Cell and PiP context menus (shared by canvas right-click and the Layers dispatch in `_on_layers_context_menu`) start with "Reveal Image Source in File Explorer": it opens the *current resolved* source (`cell.image_path`; for `pip_type == "zoom"` the parent cell's path, otherwise `pip.image_path`) — never `original_source_path`, which is only naming metadata — via `explorer.exe /select,` on Windows, `open -R` on macOS, or `QDesktopServices.openUrl` of the containing directory elsewhere; placeholders get no action, missing files a disabled action, and `_reveal_image_source` re-checks `isfile` at trigger time so a file deleted after the menu opened warns instead of launching.

## Project compatibility
- `src/model/migrations.py::PROJECT_SCHEMA_VERSION` is the project-data revision, independent of `APP_VERSION`.
- `schema_version` is written by `Project.to_dict()`; `file_version` records the writing application.
- All `Project.from_dict()` calls validate/migrate copied input. Bundle unpack also validates the project before extracting assets; ZIP/container safety gates remain separate.
- Missing `schema_version` means legacy schema 0. Migration 0→1 preserves explicit values and freezes legacy project defaults; absent raster OCR character boxes remain empty, without running OCR on load.
- Unsupported future schemas and newer app-only legacy files raise actionable errors. A newer writer using a supported explicit schema is allowed.
- Future incompatible changes must increment `PROJECT_SCHEMA_VERSION` and register each source revision in `SCHEMA_MIGRATIONS`; never just relabel old data. Add compatibility fixtures for renamed fields, default changes, and rendering semantics.
- Loading does not rewrite the source. Plain project saves and bundle saves use atomic replacement. Removed nested layouts without an image fallback are rejected rather than silently losing content.
- File → Export All Source Images snapshots unique current leaf/subcell and external-PiP paths before the folder dialog, then copies bytes on `_SourceImagesExportWorker` with modal progress and chunk cancellation. For this export, `original_source_path` is naming metadata only, never the byte source: copy the current resolved `image_path` (extracted bytes for opened bundles), not stale originals or rendered text overrides. Never save, relink, dirty the project, or release its bundle working directory. Missing legacy PiP assets not present in the archive are reported, not reconstructed; cancellation retains completed copies and removes only owned partial files.

## Editable plot documents (ILM Plot Editor)
- `src/plot_editor/` contains the preserved native plot modules and a standalone editor shell whose native file is a self-contained `*.ilmplot.svg`: standard SVG plus a versioned JSON `format: 'ilm-plot'` payload in `<metadata id="ilm-plot-document">`. `document.py`/`render.py`/`stats.py`/`mathtext.py`/`matplotlib_bridge.py` are thin compatibility aliases for the Qt- and ILM-free core, which now lives in the `ilmplot` package (`packages/ilmplot`: setuptools src-layout, `ilmplot.document`/`render`/`stats`/`mathtext`/`messages`/`bridge`; `ilmplot/__init__.py` imports no matplotlib at import time and lazy-exports `savefig`/`convert`/etc.; `ilmplot.messages` holds the English error strings and `src/plot_editor/__init__.py` registers `i18n.tr` as the translator). Parsing is strict (unknown fields, wrong types, non-finite values, duplicate ids and future `schema_version` raise `PlotDocumentError`) and never evals/pickles/runs scripts. `render.py` renders via `matplotlib.figure.Figure` + `backend_svg` under `rc_context` (fonttype none, fixed `svg.hashsalt`, `metadata={'Date': None}` — deterministic bytes) with `style_scale` multiplying typography only; figure geometry and the fixed normalized `axes_rect` never change, so viewBox and `plot_area` stay stable. `ilmplot.savefig(fig, path)` maps one rectilinear axes (lines, yerr, uniform scatter, grouped/stacked bars, text notes, ticks/spines/grid/legend) to a native `*.ilmplot.svg`; unsupported features are collected as `reasons` and fall back to a plain SVG + `FallbackWarning` (`strict=True` raises `UnsupportedFigureError` without writing); `ilmplot.convert` inspects without writing, and the strict legacy API `document_from_figure`/`export_figure` is kept.
- ilmplot package layout: `packages/ilmplot` (pyproject, src/ilmplot/, tests/, LICENSE, README). The repo never needs a pip install: `src/__init__.py` prepends `packages/ilmplot/src` to `sys.path` when it exists (in-repo copy wins over any installed ilmplot; frozen builds use the bundled module). `src/plot_editor/{document,render,stats,mathtext,matplotlib_bridge}.py` are `sys.modules` aliases to the ilmplot modules so old imports and monkeypatching keep working. PyInstaller pathex/`--paths=` include `packages/ilmplot/src` in `build_onefile.py`, `build_onefile_macos.py` and `build_installer_windows.py`. Checks: `python -m unittest verify_ilmplot_package` and `PYTHONPATH=packages/ilmplot/src python -m unittest discover -s packages/ilmplot/tests`.
- ILM boundary: `src/utils/editable_plot.py` stores applied documents as immutable content-addressed `plot-<sha256>.ilmplot.svg` under `plot_documents_root()` (sibling of the figpack cache — persistent, never swept). `SetPlotDocumentCommand` resolves the cell by id each undo/redo, stamps `plot_area.source_digest` with the new file's real SHA256, preserves crop/rotation/SVG-normalize flags on edits (`reset_image` clears them for new plots) and re-points matching `SvgTextGroup` members to the new path only when the same element keys exist. `MainWindow._on_new_plot/_on_edit_plot` capture tab/project/cell and source fingerprint before `PlotEditorWindow(doc, for_ilm=True)`; its `exec()` is only a compatibility adapter that launches the standalone editor via `QProcess.startDetached` and returns Rejected without touching the document. `PlotEditorWindow` itself is a top-level `QMainWindow` shell: File/Edit/Plot/Help menu bar (native menu bar disabled for portability) and a hero toolbar (Undo, Redo, New, Open, Save, split Plot dropdown, primary Export button) over an empty `plotWorkspace` central widget; every action is placeholder-only — triggers emit `action_requested(key)`, `plot_requested(group, chart)`, or `export_requested(format)` with no document creation, dialogs, or file I/O. All action/chart metadata lives in `src/plot_editor/actions.py` (pure Python, no Qt). Chrome uses ILM's `src.app.theme`/`icons`/`motion` as the single shared style template — `chrome.apply_app_style` sets the app palette/QSS/font scale, icons come from `src.app.icons.make_icon` with theme tokens (toolbar icons use `text`, Export uses `on_accent`), and `install_button_feedback` is applied to the toolbar; saved theme/`ui/font_scale`/`ui/motion_mode` settings are read-only. Editor widgets with no ILM counterpart (the worksheet) are styled only through token-substituted templates in `chrome.py` (`worksheet_stylesheet` uses `get_tokens`/`_font_tokens`, like `get_layers_tree_stylesheet`) — no literal colors, and ILM-styled chrome (menus/toolbar/buttons) is never restyled; the only `setStyleSheet` outside that is the transparent toolbar spacer and the worksheet view's own template. The only chart group is Line (Pure Line, Pure Scatters, Line + Scatters, Stacked Line).
- Plot Editor product rule (user): the editor must be "a reliable, efficient, professional, restrained, and low cognitive load plot editor." The left splitter area (`plotLeftArea`) hosts an OriginPro-like worksheet: `src/plot_editor/worksheet.py` is the pure-Python model (columns with designation/meta headers, grid addressing with 3 frozen meta rows, `parse_cell`/`parse_tsv`/`to_tsv`, single-step undo history capped at `HISTORY_LIMIT`, `WorksheetLimitError` on paste/column limits, listener events `('cells',c0,g0,c1,g1)`/`('rows_inserted',at,n)`/`('rows_removed',at,n)`/`('columns_inserted',at,n,animate)`/`('columns_removed',at,n)`/`('header',c0,c1)`/`('history',)` — no 'reset' event, so sections insert/remove in place and user-set column widths survive structural edits and undo); `src/plot_editor/worksheet_view.py` is the Qt layer — `WorksheetModel` plus `WorksheetView` (`plotWorksheet`) with a frozen label overlay (`plotWorksheetLabels`) sharing the same model and selection model. Row/column inserts animate 250 ms OutCubic via ILM `start_animation(..., spatial=True)` (respects `ui/motion_mode`/reduced motion; paste auto-append, removals, and tail growth are not animated). Worksheet data is in-memory only — no native-format persistence; Save remains a placeholder. Column short names are positional (A, B, C… by index) and re-letter after insert/delete — inserting before A gives A B C, never C A B. The column-header context menu offers Insert Column Left / Insert Column Right / Add New Column, and right-clicking within a resize-grip boundary (`PM_HeaderGripMargin`) shows a single "Insert Column Here" at that boundary without changing the selection. Ctrl+wheel over either grid zooms the sheet (0.5–3× via `next_zoom` in `src/plot_editor/zoom.py` — fonts, row heights, column widths and the label strip all rescale through `WorksheetView.set_zoom`; Ctrl+0 resets; zoom is per tab, never saved or undoable). Non-UI check: `python -m unittest verify_plot_editor_worksheet`. Non-UI check: `python -m unittest verify_plot_editor_actions`; UI behavior is verified by the user. File → Open Plot Editor also launches it detached. `CanvasScene.cell_double_clicked` fires from `CellItem.mouseDoubleClickEvent` only for non-label cells with no selected PiP and no active crop.
- The right splitter area (`plotRightArea`) hosts `PlotCanvas` (`src/plot_editor/plot_canvas.py`), a frameless `QGraphicsView` rendering the plot SVG via `QGraphicsSvgItem` + shared `QSvgRenderer` (NoCache so it stays crisp when zoomed), scene background from the ILM `canvas_bg` token, Ctrl+wheel zoom ×1.1^steps anchored under the cursor (clamped to 0.1–20, disables auto-fit), middle-drag pan, fit-to-view on resize until the user zooms. Picking a chart type or pressing Plot/Ctrl+Return builds one series per selected Y column (`src/plot_editor/plot_data.py` `build_series`: X = nearest selected X left of the Y, else nearest X left in the sheet, else 1-based row index labelled 'Row'; non-numeric cells skipped; axis titles = long_name or column letter plus ` (units)`; legend/curve label = first non-empty Comments line, else long_name, else column letter (OriginPro's @LM default, no units); no selected Y or no numeric points raises `PlotSelectionError` shown as an info dialog, canvas untouched). `src/plot_editor/plotting.py` renders with bare `matplotlib.figure.Figure`/`FigureCanvasSVG` (matplotlib defaults — no ILM theme, no pyplot): `pure_line`/`pure_scatters`/`line_scatters`, and `stacked_line` offsets each curve to sit just above the previous (Origin "Stack Lines by Y Offsets"); legend only when >1 series; `figure_svg` serializes via `fig.savefig(format='svg')` and the bytes feed `show_svg`. Each right area also has a slim always-visible `PlotTitleField` (`title_field.py`, `plotTitleField`): a dashed-border `placeholder`-token prompt label, double-click switches to a centred `QLineEdit`, Enter/focus-out commits (empty reverts to the prompt, `title_changed` marks the tab dirty and records an 'Edit Title' undo entry), Esc cancels, hover shows a `text`-token dashed border. The preview canvas also draws the title: `PlotTab._render_preview` re-renders on every title commit (matplotlib figure with `title=` for fresh plots, or a cloned loaded document through `render_document` when no replot happened); exports and the saved `ilm-plot-document`'s `title` include it — `tab.save` clones a kept loaded document so a title-only edit re-renders the stored SVG. Non-UI check: `python -m unittest verify_plot_editor_plot verify_plot_editor_export`. Committed worksheet edits re-plot live: `PlotTab._refresh_from_sheet` runs on each `('history',)` event (Enter/focus-loss commits, paste, structural ops, undo/redo — never per keystroke), rebuilding series for the existing `plot_columns` and chart with zoom kept; an unplottable result keeps the previous preview. With a legacy base, `effective_document` copies x/y/tick labels from the sheet so only the base's look is reused. Export (`src/plot_editor/export.py`) writes all six menu formats once a plot exists (menu items + toolbar button stay disabled until then): `ilmplot` builds a `PlotDocument` via `document_from_plot` (native defaults for size/typography/axes — it intentionally differs from the matplotlib-default preview; per-series `Ci` colors resolved to hex, style map line/marker per chart key, stacked offsets baked into y) and saves through the unchanged `render.save_document`; PDF/SVG (`metadata={'Date': None}`) and 300-dpi PNG/TIFF/JPEG go through `fig.savefig` with the same atomic temp-sibling + `os.replace` write pattern. `with_suffix` normalizes extensions (`a.svg` → `a.ilmplot.svg` for ilmplot). Save path dialogs remember the last export directory; failures surface as a warning, no success popup. Non-UI checks: `python -m unittest verify_plot_editor_plot verify_plot_editor_export`. Focus rule: worksheet edit shortcuts (Ctrl+X/C/V/A, Delete) act on the worksheet only while the worksheet view, its `_labels` overlay or a descendant (e.g. a cell editor) has focus — `PlotCanvas` takes focus on every mouse press and accepts Delete/Backspace `ShortcutOverride` so its `keyPressEvent` deletes the selected note/fill instead; Edit ▸ Delete with canvas focus goes through `plot_canvas.delete_selected`.
- The Plot Editor is tabbed: the central widget is a `QTabWidget` (`plotTabs`, closable/movable/documentMode) of `PlotTab`s (`src/plot_editor/tab.py`) — each tab owns its worksheet, `PlotCanvas`, path/title, dirty flag and `PlotState` (series, chart, plotted columns, optional loaded document); a `changed` signal drives tab text (`title + ' *'`), tab tooltip, window title (`'<title> — Plot Editor'`), undo/redo and export enablement. File ops write self-contained `*.ilmplot.svg` (`src/plot_editor/plot_file.py`): the `ilm-plot-document` node is unchanged except for the optional `x_tick_labels` field (`[[position, label], ...]` categorical x ticks — omitted from `to_dict` when null so unlabeled files stay byte-identical; note older builds reject files that contain it) and a second, editor-owned `<metadata id="ilm-plot-worksheet">` node stores the raw worksheet (designations/meta/values, chart key, plotted columns) — parsed strictly (unknown keys, future schema, bad designations, non-finite values all rejected), ignored by ILM (whose content-addressed store re-renders documents without it). Files without the node (ILM/older saves) rebuild a worksheet from series (shared-x dedupe → X,Y[,X,Y], chart inferred from the first series' linestyle/marker; a series whose x values are all `x_tick_labels` positions rebuilds a `Label` column of tick strings). Plotting treats a selected `Label` column like a selected `X` in the nearest-left pool (but the unselected-X fallback only ever picks `X` columns): a Label X plots at row positions 1,2,3… with the cell's display text as tick labels (`plot_data.tick_label_map` feeds `make_figure`/`document_from_plot`/`render._build_figure`). Inline `$...$` math renders in title, axis titles, legend, Label ticks and the worksheet's meta cells: `mathtext.safe_text` is applied only at draw time (stored text stays raw — invalid segments get their `$`s escaped to render literally, `\LaTeX`/`\TeX` are rewritten to `\mathrm`), while `math_render.math_pixmap` (LRU-cached bare-Figure PNG → QPixmap, None on failure) drives the meta-cell delegate and the title field's pixmap display. The document also carries an optional `style` object (`document.py`: `TextStyle`/`TitleStyle`/`AxisStyle`/`GridStyle`/`LegendStyle`/`FrameStyle`/`PlotStyle`, strictly parsed, every key omitted when default so unstyled files stay byte-identical — older builds reject styled ones); `render._build_figure` applies it (fonts, underline via a draw-time `Artist`, tick locators/formatters/rotation/scale, grid and frame look, legend frame/ncols/prop), `_prepare_svg` keeps each `<text>` node's own first CSS family so per-element fonts survive, and `render.element_regions(document)` (figure-fraction, top-left bboxes + decimated series points, canonical-cached) plus `render.export_document(document, path, fmt, dpi)` exist for phase-2 editor hit-testing and native export (`python -m unittest verify_plot_style`; goldens live in `test_fixtures/`). New/Open/Save/Save As are real; Export → ILM Plot is Save As; closing a dirty tab or the window prompts Save/Discard/Cancel; closing the last tab leaves a fresh Untitled one. A positional file argument opens it in the first tab. ILM double-click/Edit Plot treats the source `.ilmplot.svg` as the project file when ILM supplies `source_path` — except for files under `plot_documents_root()` (or when that check fails), which are ILM's immutable content-addressed store and go through a verbatim `--ilm-copy` (`src/plot_editor/ilm_bridge.py`; temp file deleted after load, tab detached — `path=None`, dirty, 'Plot from ILM' — so Save is Save As; user files open as linked tabs where Ctrl+S writes back in place; default New Plot documents skip the copy and just open a blank tab). The no-node fallback (`worksheet_from_document`) splits axis titles via `split_axis_title` — `long_name`/`units` come from `'Time (s)'`-style labels and the series label lands in `comments`, so legends reproduce the original text. In-place edits are **overrides** (`src/plot_editor/overrides.py`, Qt-free `PlotOverrides`/`SeriesOverride` keyed by Y-column index, strict `from_dict`, `OverridesError`): a set field wins over anything worksheet-derived, `None` means "not overridden"; `overrides_from_document` seeds them from a loaded doc (style cloned, only fields differing from `PlotDocument()` defaults), `effective_document(base, series, chart, title, overrides)` composes base-or-`document_from_plot` + overrides into the validated doc, and `remap_series_keys`/`_shift_columns` shift override keys and `plot_columns` on worksheet column insert/remove. Persistence: the worksheet node is `schema_version` 2 **only** when `overrides` is emitted (plain files stay v1 and old-editor-readable; the reader accepts v1, v2's optional strictly-parsed `overrides`, and rejects higher). `PlotState.legacy_base` keeps a no-worksheet file's document as the render base until the tab is re-plotted; otherwise the doc regenerates from the series. Preview (`PlotTab._render_preview`, `PlotCanvas.show_svg(..., keep_view)` keeps zoom/scroll on same-size re-renders), save and exports all go through the native renderer — `export_plot(document, path, key)` → `render.save_document` for ilmplot / `render.export_document` otherwise — so preview == saved == ILM. In-place editing UI: `PlotCanvas.set_regions` consumes `render.element_regions` fractions; hover shows a single reused dashed `text_sec` `QGraphicsRectItem` and left-double-click emits `element_activated(key, global_pos)` — keys `'title'`, `'xlabel'`, `'ylabel'`, `'xticks'`, `'yticks'`, `'legend'`, `'frame'`, `'series:<id>'` (priority legend>title>xlabel>ylabel>xticks>yticks>series>frame; series hit = 5 view-px polyline proximity via Qt-free `hit_test.py`). `ElementPanel` (`element_panel.py`, frameless `Qt.Tool`, `chrome.element_panel_stylesheet`; an app-level event filter installed while open closes it on outside clicks but never while a modal widget or popup is active) opens at the cursor and writes **only** through `tab.update_overrides` (text fields commit on `editingFinished`, spins use `setKeyboardTracking(False)`, toggles/combos immediate; title text routed via `tab.set_plot_title`). Every optional row ends in a `reset`-icon button that clears just that override (spins show the effective inherited value with the button disabled; decimals/spacing/min/max are `QLineEdit`s where empty = Auto); the font family row is an editable combo with a `MatchContains` completer resolved through `render.resolve_font_family`. `update_overrides` deep-copies `PlotOverrides` before applying (Qt-free `overrides.apply_update`) and rolls back to the snapshot on any exception, so a bad edit can never crash a slot; Every successful non-no-op `update_overrides` edit goes through `record_overrides_edit` into the worksheet's undo history as 'Edit Plot' (in-place `PlotOverrides` restore keeps open element panels valid — a panel re-syncs on `changed` and closes when its element vanished, e.g. undoing Add Fill). `app.py` also installs a `sys.excepthook` that shows a warning instead of aborting. Per-element Reset goes through `overrides.reset_element`, and a "Reset formatting" `QToolButton` overlays the plot area's bottom-right (child of `plotRightArea`, kept at 12 px margin via a resize event filter) that replaces all overrides with a fresh `PlotOverrides` after a confirm. The renderer clips series to set xlim/ylim itself (Qt-free `render.clip_series_to_view`, log-space Liang–Barsky, NaN breaks, boundary points, `markevery` mask) because QtSvg ignores SVG clipPath; tick prefix/suffix use a real `ticker.Formatter` subclass so the wrapped formatter still receives `set_locs`. Both the editor window and the ILM welcome window accept dropped `*.ilmplot.svg` files (`ilm_bridge.is_native_plot_path`; welcome drops route through `MainWindow._on_open_plot_editor(path)`), and new glyph icons (`bold/italic/underline/align_*/reset.svg`) share the `currentColor` icon pipeline. Non-UI checks: `python -m unittest verify_plot_editor_file verify_plot_editor_ilm_copy verify_plot_overrides verify_plot_element_hit`.
- The Plot Editor's UI language follows ILM's saved `language` setting read once at startup (read-only, `chrome.saved_language`, no editor-side toggle or live switching); all strings live in `src/plot_editor/i18n.py` (`tr(key)`, en/zh — wording mirrors `src/app/i18n.py`), Qt-free modules raise translated messages via `tr` too, and plot/file content (axis titles, 'Row', column letters, chart keys, override JSON) is never translated. `python -m unittest verify_plot_editor_i18n` checks table completeness, placeholder parity, and that every `tr` key is used.
- Style presets (`src/plot_editor/presets.py`, Qt-free): preset types are chart *group* keys (`plot_type_for_chart`; all four line charts are 'line'), stored as `<root>/<type>/<slug>.ilmstyle.json` (`format: 'ilm-plot-style'`, `schema_version: 1`) plus `<root>/defaults.json`, where `root` is `QStandardPaths.GenericDataLocation/AcademicFigureLayout/ImageLayoutManager/plot_styles` (`chrome.preset_root`, never the translated app name); a non-deletable 'Standard' built-in means "no overrides" and is the implicit default, a non-Standard default auto-applies only to freshly plotted tabs with empty overrides, and `capture`/`apply` are formatting-only — axis `step`/`prefix`/`suffix`/`scale`/`reversed`, text, limits and data are excluded. The per-tab 'Style' button sits left of 'Reset formatting' (`plotStylePresets`), Plot → 'Plot Style…' opens `style_manager.StyleManagerDialog` (tree by type, rendered sample preview, summary), and the element-panel line-style/marker combos are icon-only via `style_icons.style_icon` (cached by kind/code/colour/dpr). Verify: `python -m unittest verify_plot_presets`.
- The Plot Editor has its own guided tutorials (Help → Tutorials…, action `tutorials` in `actions.py`'s `HELP_MENU`): the lesson model is Qt-free `src/plot_editor/tutorial_lessons.py` — `Step(key, title_key, body_key, target, action, ready)` where `ready(tab, ctx)` predicates read only worksheet/plot/overrides/title/path/dirty state and `ctx` holds lazy baselines (theme palette, prior non-pristine flag for the reset step); `fill_sample_data(ws)` is the shared undoable sample fill (A=X 0–5, B/C=Y) used by both the guided action and the `styling` setup. `src/plot_editor/tutorial.py` carries `TutorialController` (250 ms ready polling, practice tab via `window._add_tab()` titled 'Practice — <lesson>', pause when another tab is current, Exit leaves the tab open), the non-modal `TutorialCard` (Tool window, bottom-right of the editor), `TutorialHighlight` (accent ring overlay hosted by the window, transparent for mouse), and `TutorialChooserDialog` (per-lesson title + summary buttons). Guided actions: `fill_sample` and `plot_sample` (selects B:C, `tab.plot_current('line_scatters')`). All copy lives in the editor `i18n.py` (`tut_*` keys). Verify: `python -m unittest verify_plot_editor_tutorial` (Qt-free).
- The native document also supports the kinds `violin` (`groups` of `ViolinGroup`), `ridgeline` (line `series`) and `stacked_column` (`categories` of `StackCategory` + `x_tick_labels`), plus per-kind options (`ViolinOptions`/`RidgeOptions`/`StackOptions`), `annotations`, `brackets`, `legend_location` 'outside right' and `FrameStyle.hide_left`/`hide_bottom`; KDE/box/jitter math lives in Qt-free `src/plot_editor/stats.py` (scipy-free numpy `gaussian_kde`), and because QtSvg ignores clipPath `render.clip_polygon_to_view` clips fills in data space when xlim/ylim are set. `SCHEMA_VERSION` stays 1, so older ILM builds reject these kinds. Verify: `python -m unittest verify_plot_kinds`.
- Editor support for the new kinds (phase B): chart groups are `line` (adds Ridgeline), `violin` and `column` (100% Stacked / Stacked Column); `export.CHART_KIND` maps chart → document kind (+ stacked `percent`). Wide-format builders in `plot_data.py`: `build_groups` (one violin per Y column) and `build_categories` (one category per Y column; bar names from the nearest Label/X left of the first Y or in the sheet, else "0","1",…; non-numeric → 0, negatives clamped; percent-mode y title is the fixed 'Percentage (%)'). Colour themes live in Qt-free `palettes.py` (`THEMES` from NCPlotGenerator, `theme_colors`/`default_theme`; `first` interpolates only past the list, `spread` = ridgeline; `default` is the tab10 cycle identical to the old `Ci` colours). `PlotOverrides` gains `palette`/`palette_reverse`, the three kind-option objects, `annotations`/`brackets` (content, saved with the plot; presets never capture them); presets also carry palette and kind options per group and each group gets its own 'Standard'. Hit-testing adds `violin:`/`stack:`/`annotation:`/`bracket:` keys (annotation > bracket > legend > … > violin/stack > series > frame); element panels cover item label/colour plus per-kind sections, the frame panel adds a themed colour-strip combo + reverse + hide left/bottom, and Plot → Add Note / Add Significance Bracket create content (bracket enabled only for violin/stacked with ≥2 items). `plot_file` maps kind ↔ chart and rebuilds worksheets per kind (violin → one Y per group, stacked → Label column + one Y per category); `items_from_document` is the worksheet-less fallback. Verify: `python -m unittest verify_plot_editor_kinds`. Column group also has a plain grouped `column` chart (first in the group; StackOptions.grouped=True, percent=False; side-by-side bars, bar_width = group width) — also the style manager's column preview sample.
- Box / Column + Points / Histogram / horizontal bars (phase C): the `violin` document kind is the "groups of raw values" family — `ViolinOptions.body` ∈ `'violin'` | `'none'` (box plot: coloured box at `fill_alpha`, caps, hollow `#333333` outliers beyond 1.5·IQR when `show_outliers` and points are off) | `'bar'` (mean column of `bar_width`, `bar_error` sd/sem/none as a capless `#333333` bar), plus `box_width` (None → 0.16 inside a violin/bar, 0.5 standalone). Chart keys `box`/`column_points` live in the `violin` group (display 'Distribution', preset folder key unchanged) and `export.VIOLIN_BODY` is forced onto `doc.violin.body` in `effective_document` from the chart key, like `percent`/`grouped`; a plain `violin` chart with no overrides keeps `doc.violin = None` so old files render byte-identical. `histogram` is a real kind (`groups` + `HistOptions`: `bins` xor `bin_width`, `density`, `style` bars/step, `fill_alpha` 0.5, edge, `kde` + `bandwidth`); all groups share `render._hist_bins` edges (numpy `'auto'` when unset), bars are one step-outline Polygon per group with gid `ilmplot-hist-<id>` → regions `hists` → hit key `hist:` → `_build_hist_item`; x is numeric (no bar/group-label section, brackets/x_tick_labels rejected), default titles are the value title on x and 'Count'/'Density' on y via `export.default_axis_titles` (also the single source for the horizontal swap and 'Percentage (%)'). Horizontal bars are chart keys `bar`/`stacked_bar`/`stacked_bar_pct` (`export.HORIZONTAL_CHARTS`, column group display 'Column & Bar') → `StackOptions.horizontal`; `_draw_stacked` keeps its (category, value) maths and swaps through `P(c, v)` at emit time, `_build_figure` treats y as the categorical axis (ticks, no log, no step/minor locators). Capabilities `box_plot`/`column_points`/`histogram`/`horizontal_bars` are stamped by `required_capabilities` and `plot_file.worksheet_to_dict` (which now emits `requires` even without overrides). Element panels seed `overrides.violin`/`overrides.histogram` from the *effective* options on first edit so chart-specific defaults survive. The `violin:` panel is one builder but body-aware (`element_panel.violin_panel_keys(body)` → title/section keys `panel_violin`/`panel_box`/`panel_column_points`): the violin layout is unchanged, Box hides the inert Edge/Enhance-contrast/Bandwidth rows and shows Show outliers only while points are off, Column + Points shows Bar width/Error bars/Edge rows and folds Box width under Show box; dependent blocks live in `_subform` widgets whose visibility (and the panel's `adjustSize`) is bound through `_syncs`. Verify: `python -m unittest verify_plot_chart_types` and `packages/ilmplot/tests/test_chart_types.py`; `build/baseline_capture.py` (gitignored) re-renders five legacy violin/column docs plus two plain line docs for a byte-identity check.

- The Label Cell Settings panel (shown for a strip label) is split in two: under "— This label —" the placement/tier/font/size/weight/colour/align/offset rows and Rotate-90° button edit only the selected label's `TextItem` via `label_item_property_changed`, and two buttons provide the explicit apply-to-all — "Apply Style to All" reuses `apply_style_to_group`, "Apply Position to All" emits `apply_label_position_to_all` which writes the `Project.label_align`/`label_offset_*` defaults and clears every strip label's overrides in one undo macro. Under "— All labels —" the scheme/row-height/column-width rows stay project-wide. `TextItem.label_align`/`label_valign`/`label_offset_x`/`label_offset_y` (schema 3) are optional per-label overrides — `None` inherits the project value; `Project.effective_label_align`/`effective_label_valign`/`effective_label_offsets` and `label_strip_is_vertical` (true for `label_col_left`/`label_col_right` placement) are the single resolution points used by the canvas, both exporters, and the label-drag ghost/tracer. `src/utils/label_strip_render.py` is the single strip-label renderer for canvas/PNG/PDF: horizontal strips honour `label_align`, vertical strips `label_valign`, and the alignment is applied inside the rotated drawing frame (each 90° clockwise turn remaps the axes, so a non-centred label rotated 90° keeps its device-space edge instead of sliding to an end — intentional change). `LabelAlignPicker` mirrors the orientation: `set_orientation("vertical")` makes it a fixed 40×96 column with top/middle/bottom slots (Up/Down keys also work); the label-cell view emits `label_valign` when vertical. The shared `label_item_group` ("Selected Label" section) is only shown for in-cell numbering labels, never in the label_cell view.
- `style_locked` is implicit, not a checkbox: per-label font/size/weight edits set it, and both panels offer "Reset to Tier Style" while locked; only the in-cell Selected Label panel shows the "Custom style" hint. The strip-label placement dropdown excludes the explicit "In-cell" option and uses its own option mapping for population, emission, and retranslation. Resetting emits a `label_tier` change, which re-applies the tier's `label_style_fields` and clears the lock; Apply Style to All also clears locks; a tier change never locks.

## Text size matching architecture
- Text groups (`Project.svg_text_groups`, `SvgTextGroup.font_size_pt`) are **points in the final figure**.
- `src/utils/panel_scale.py::panel_mm_per_unit` is the single source of truth for how many mm one image
  unit covers (fit/crop/rotation/layout); both SVG and raster pipelines divide by it.
- SVG: `svg_text_utils.get_svg_override_bytes_for_cell`; raster: `raster_text_utils.build_raster_override_spec`
  (+ `apply_raster_text_overrides`). Exporters go through `src/utils/text_overrides.overrides_for_cell`.
- Canvas: `CanvasScene.refresh_layout` puts both overrides in the per-cell fingerprint and passes them to
  `CellItem.update_data` → `ImageProxy.get_pixmap(..., svg_override_bytes, raster_override)` which caches per
  (path, content-hash), so the same file can render differently in different panels.
- Group overrides are written into the SVG in **user units** (`font-size:<n>px`, 1 px = 1 user unit) via `svg_mm_per_unit`, never in `pt`: QtSvg resolves `pt` at ~1.24 px/pt, not the `96/72` the page maths assumes, which rendered synced SVG text ~7% small and de-synced it from raster panels. `_set_font_size`/`_walk_normalize`/`_apply_group_font_sizes` take a `unit`; per-cell `svg_normalize_text` still writes `pt` (changing it would resize existing figures).
- `raster_text_utils.ink_ratio_for_text()` converts a label's ink-box height to an em. The ratio depends on the characters present (x-height 0.54, cap 0.72, ascender 0.73, +0.205 for descenders, 0.94 for CJK); the old single 0.72 constant biased the estimate by up to 30% ("Response", "Time (s)", CJK) and that error landed directly on the group scale.
- The contract both pipelines can hit exactly is the **em size on the page**. Residual differences in glyph *ink* are rasteriser-dependent (QtSvg hints vector text, so its ink runs a few percent shorter than an equivalent raster panel) and are not a code defect. `python -m unittest test_text_size_sync` asserts the exact em for both pipelines, tight raster-to-raster convergence, and a documented end-to-end bound.
- OCR backends live in `src/utils/raster_text_ocr.py`; selection is in Preferences → Text Detection
  (`ocr_backend` / `ocr_command` QSettings). Default and shipped backend: `rapidocr` (+ `onnxruntime`).
- Raster safety checks (`analyze_region`, `raster_text_utils.py`) judge a box's *own interior* only:
  background = dominant colour (robust to mixed-height glyphs touching the box edge), "touching" =
  foreground continuing from just inside to just outside an edge (real external object, not the
  label's own ink). `_classify_text_pixels` additionally splits interior foreground into connected
  components and keeps only ones reaching the text line's shared baseline — anything else (e.g. a
  diagram pointer sitting in the dead space a box picks up above short letters when the same line
  has tall ones) is excluded from extraction/scaling and left un-erased on the canvas
  (`RasterTextRegion.foreign_excluded`). Floating blobs that ARE text ("-", i-dots, accents, ":") are
  rescued using the OCR's per-character boxes as the judge (`RasterTextRegion.chars`, filled by every
  backend that can: RapidOCR word boxes, Tesseract `image_to_boxes`, command JSON `chars`): a blob under
  a character in `_FLOATING_CHARS` / with a combining mark / CJK is text; under a plain letter it's
  foreign. With no char info, geometry falls back to x-height band + centred-diacritic rules.

## Licensing / release preparation
- `licenses/` contains vendored full license texts plus `origins.json` (source + SHA256). Never paraphrase license text; re-vendor exact upstream files if a version bumps.
- `python build_licenses.py` stages `build/licenses-*` (or `--output <new dir>`): per-component license/METADATA copies from installed RECORD files, `components.json` inventory (`source_status: incomplete`), `index.html` viewer, Python runtime license, and `ImageLayoutManager-<ver>-application-source.zip` (application source only — NOT a complete corresponding-source bundle). `--check-release` always exits 2 while pending items remain; there is no "approved" override.
- `prepare_licenses()` is called by `build_installer_windows.py`, `build_onefile.py`, `build_onefile_macos.py` and bundled via `--add-data` into `licenses/`; the About dialog's "Licenses and source…" (`src/app/license_dialog.py`) reads `sys._MEIPASS/licenses` when frozen, repo `licenses/` + NOTICE in development, and renders plain text only (no network).
- Missing license files for a distribution are a hard error unless an entry in `build_licenses.FALLBACKS` matches the exact installed version AND the SHA256 recorded in `licenses/origins.json`.
- Known limitation: the manifest intentionally marks `source_status: incomplete` — native-library/dependency corresponding-source auditing and publication are still open items; do not treat the staging output as release clearance.
- Verify with `python -m unittest verify_licenses test_windows_packaging`.

### Corresponding-source index
- `python build_source_index.py collect` requires a built candidate matching `src/version.py` (`build/store-candidate-*/dist/ImageLayoutManager/_internal/licenses/components.json`) plus matching recorded manifests under `build/`. Provenance discovery is semantic and version-matched, never tied to a timestamped candidate name. `render` writes `SOURCES.md` and `check` verifies both stay in sync.
- `SOURCES.md` is generated - edit `build_source_index.py`, never the Markdown. Recorded per-component status strings are reproduced verbatim and must never be upgraded by hand. `licenses/sources.json` must not contain `application_source_sha256`: that file is included inside the source archive, so the hash would be self-referential; the generated `components.json` is the authority for the archive hash.
- Regenerate `licenses/sources.json` and `SOURCES.md` whenever the app version or any dependency version changes.
- `source_status` in `components.json` stays `incomplete` - publishing the index does not by itself make correspondence verified.
- Verify with `python -m unittest verify_source_index`.

## Windows Store / MSIX packaging
- Fresh isolated onedir (preserves existing outputs): `python build_installer_windows.py --onedir-only --output-root build\store-candidate-<unique>` -- the output root must not already exist; Inno Setup/winget are skipped on this path.
- Package layout + unsigned MSIX: `python build_msix.py --bundle <out>\dist\ImageLayoutManager --output <new-dir> --identity-name <name> --publisher <CN=...> --publisher-display-name <name> [--makeappx <path-to-makeappx.exe>]`. Without `--makeappx` it writes layout only (no fake .msix). MakeAppx.exe can be obtained locally from the `Microsoft.Windows.SDK.BuildTools` NuGet package extracted under `build/sdk-tools-*` (no system install); verify its Microsoft Authenticode signature before use.
- `python -m unittest verify_msix` covers manifest structure/escaping, version rules, path containment and isolated-build routing.
- Isolated builds spawn separate PyInstaller processes with a child-only PATH restricted to the selected interpreter and Windows directories; blanket Qt binary/data collection and matplotlib submodule collection are omitted. This prevents unrelated installed applications or the base Conda environment from supplying DLLs. The default Inno route is unchanged.
- `python audit_release.py inventory --bundle <onedir> --output <new-audit-dir>` records relative paths, file hashes and embedded Python modules. `python audit_release.py sources --inventory <audit-json> --output <new-source-dir>` downloads exact PyPI sdists with SHA256/size checks. RECORD matches are provenance candidates, not proof of complete license or corresponding-source coverage. Keep audit outputs and downloads under ignored `build/`.
- Frozen Windows rendering checks must use the native `windows` Qt platform, not the fontless offscreen test setup. Put math-text fixtures in Python files rather than double-quoted PowerShell command strings, which expand `$` expressions before Python sees them.
- `licenses/native/**` holds upstream notices extracted from version-matched native sources (Qt modules incl. QtPdf/Chromium, Mesa, LLVM, MuPDF, GEOS, Conda runtime packages). Their `origins.json` records add `component`, `component_version`, optional `platform`, and a required `binding`: `distribution` (installed package version must match) or `runtime_file` (a path under `sys.prefix` whose SHA256 must match). `build_licenses._native_notice_components()` groups them into extra manifest components after the Python distributions; every origins entry — not just the mandatory seven — is hash-verified. Tests that stage licenses with mocked distributions must filter out `component` records, since their bindings reference real installed packages.
