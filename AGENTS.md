- The Layers panel (`src/app/layers_panel.py`) has two shapes. In grid mode it groups cells by row/column — a stable structural identity kept across swaps, unrelated to draw order — and cells are *not* draggable: z_index is meaningless while cells can't overlap (the row items carry no drag/drop flags and `MainWindow._on_layers_reorder_requested` ignores stray cell reorders). In freeform mode (`project.layout_mode == 'freeform'`, detected by `refresh()` → `tree.cells_reorderable`) it switches to a Photoshop-style flat layer list that *is* the z-stack: top row = frontmost (sort key `(z_index, creation index)` descending — creation order is the canvas's tie-break for equal zValues), no row headers, and PiP children shown reversed so they read front-to-back like their parents. Drag mechanics are Photoshop-like: the pointer's vertical half inside a row picks the boundary above/below it, `_BranchlessTree.paintEvent` draws an accent insertion line at that boundary (Qt's own drop indicator is disabled), hovering another cell's expanded inset rows maps to "behind that cell", and empty space below the list means the back of the stack. A drop emits `reorder_requested(dragged_id, target_id, place_above)` where place_above means "in front of the target" — never a reparent — for `MainWindow._on_layers_reorder_requested` to turn into `ReorderZIndexCommand` (renumbers every leaf cell's `z_index` to its rank — compact and deterministic, unlike `ZIndexChangeCommand`'s raw ±1 used by Bring to Front/Send to Back, which both remain) or `ReorderPipItemsCommand` (reorders `cell.pip_items`; list order *is* the PiP stack, last = frontmost). Drops that would land the cell on the stack slot it already occupies are skipped so undo history stays clean. PiP insets stay draggable in both modes — they overlap their host cell regardless of layout. A small "Z±n" chip (`_ROLE_ZIDX`) only appears on a grid-mode cell row once its `z_index` differs from the default 0 (in freeform the row's position already *is* its rank, so the chip is suppressed there).

## Project compatibility
- `src/model/migrations.py::PROJECT_SCHEMA_VERSION` is the project-data revision, independent of `APP_VERSION`.
- `schema_version` is written by `Project.to_dict()`; `file_version` records the writing application.
- All `Project.from_dict()` calls validate/migrate copied input. Bundle unpack also validates the project before extracting assets; ZIP/container safety gates remain separate.
- Missing `schema_version` means legacy schema 0. Migration 0→1 preserves explicit values and freezes legacy project defaults; absent raster OCR character boxes remain empty, without running OCR on load.
- Unsupported future schemas and newer app-only legacy files raise actionable errors. A newer writer using a supported explicit schema is allowed.
- Future incompatible changes must increment `PROJECT_SCHEMA_VERSION` and register each source revision in `SCHEMA_MIGRATIONS`; never just relabel old data. Add compatibility fixtures for renamed fields, default changes, and rendering semantics.
- Loading does not rewrite the source. Plain project saves and bundle saves use atomic replacement. Removed nested layouts without an image fallback are rejected rather than silently losing content.
- File → Export All Source Images snapshots unique current leaf/subcell and external-PiP paths before the folder dialog, then copies bytes on `_SourceImagesExportWorker` with modal progress and chunk cancellation. For this export, `original_source_path` is naming metadata only, never the byte source: copy the current resolved `image_path` (extracted bytes for opened bundles), not stale originals or rendered text overrides. Never save, relink, dirty the project, or release its bundle working directory. Missing legacy PiP assets not present in the archive are reported, not reconstructed; cancellation retains completed copies and removes only owned partial files.

## Text size matching architecture
- Text groups (`Project.svg_text_groups`, `SvgTextGroup.font_size_pt`) are **points in the final figure**.
- `src/utils/panel_scale.py::panel_mm_per_unit` is the single source of truth for how many mm one image
  unit covers (fit/crop/rotation/layout); both SVG and raster pipelines divide by it.
- SVG: `svg_text_utils.get_svg_override_bytes_for_cell`; raster: `raster_text_utils.build_raster_override_spec`
  (+ `apply_raster_text_overrides`). Exporters go through `src/utils/text_overrides.overrides_for_cell`.
- Canvas: `CanvasScene.refresh_layout` puts both overrides in the per-cell fingerprint and passes them to
  `CellItem.update_data` → `ImageProxy.get_pixmap(..., svg_override_bytes, raster_override)` which caches per
  (path, content-hash), so the same file can render differently in different panels.
- Group overrides are written into the SVG in **user units** (`font-size:<n>px`, 1 px = 1 user unit) via `svg_mm_per_unit`, never in `pt`: QtSvg resolves `pt` at ~1.24 px/pt, not the `96/72` the page maths assumes, which rendered synced SVG text ~7% small and de-synced it from raster panels. `_set_font_size`/`_walk_normalize`/`_apply_group_font_sizes` take a `unit`; per-cell `svg_normalize_text` still writes `pt` (changing it would resize existing figures).
- `raster_text_utils.ink_ratio_for_text()` converts a label's ink-box height to an em. The ratio depends on the characters present (x-height 0.54, cap 0.72, ascender 0.73, +0.205 for descenders, 0.94 for CJK); the old single 0.72 constant biased the estimate by up to 30% ("Response", "Time (s)", CJK) and that error landed directly on the group scale.
- The contract both pipelines can hit exactly is the **em size on the page**. Residual differences in glyph *ink* are rasteriser-dependent (QtSvg hints vector text, so its ink runs a few percent shorter than an equivalent raster panel) and are not a code defect. `python -m unittest test_text_size_sync` asserts the exact em for both pipelines, tight raster-to-raster convergence, and a documented end-to-end bound.
- OCR backends live in `src/utils/raster_text_ocr.py`; selection is in Preferences → Text Detection
  (`ocr_backend` / `ocr_command` QSettings). Default and shipped backend: `rapidocr` (+ `onnxruntime`).
- Raster safety checks (`analyze_region`, `raster_text_utils.py`) judge a box's *own interior* only:
  background = dominant colour (robust to mixed-height glyphs touching the box edge), "touching" =
  foreground continuing from just inside to just outside an edge (real external object, not the
  label's own ink). `_classify_text_pixels` additionally splits interior foreground into connected
  components and keeps only ones reaching the text line's shared baseline — anything else (e.g. a
  diagram pointer sitting in the dead space a box picks up above short letters when the same line
  has tall ones) is excluded from extraction/scaling and left un-erased on the canvas
  (`RasterTextRegion.foreign_excluded`). Floating blobs that ARE text ("-", i-dots, accents, ":") are
  rescued using the OCR's per-character boxes as the judge (`RasterTextRegion.chars`, filled by every
  backend that can: RapidOCR word boxes, Tesseract `image_to_boxes`, command JSON `chars`): a blob under
  a character in `_FLOATING_CHARS` / with a combining mark / CJK is text; under a plain letter it's
  foreign. With no char info, geometry falls back to x-height band + centred-diacritic rules.
