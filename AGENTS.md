# ImageLayoutManager — agent notes

## Environment
- Conda env: `imagelayout` (`conda env create -f environment.yml`); `git` is not on PATH in the default shell.
- Run the app: `python main.py`; headless CLI: `python cli_main.py --help`.
- Windows packaging: keep Qt DLLs under `_internal/PyQt6/Qt6/bin`, not duplicate `_internal/Qt6*.dll` copies from Conda. Inno Setup upgrades must also remove obsolete top-level Qt DLLs with the targeted `[InstallDelete]` rule; copying a clean bundle over an old installation leaves stale DLLs behind. `python -m unittest test_windows_packaging` checks that cleanup stays limited to those files.

## Verification
- Tests are plain `unittest` modules at the repo root (no pytest config):
  - `python -m unittest test_svg_text_groups` — project-wide SVG text groups (canvas fingerprint, scale, export).
  - `python -m unittest test_raster_text` — raster text size matching (OCR → regions → resize → export).
  - `python -m unittest test_raster_text_overlay` — rounded text envelopes, protected pixels, preview selection, scaling, and theme colors.
  - `python -m unittest test_project_migrations test_project_bundle_compatibility` — legacy/schema migrations, future-version guards, plain/bundle parity, rendering and save integrity.
  - `python -m unittest test_welcome_drop` — welcome-window saved-project drag/drop, filtering, and opener routing.
  - `python -m unittest test_help_dialog` — bilingual in-app guide pages, rich-text markup, and shortcut/content checks. The offline guide content is embedded in `src/app/help_dialog.py`; tab labels live in `src/app/i18n.py`.
  - `python -m unittest test_tutorials` — isolated practice tabs, real SVG assignment/save actions, pause/replay/exit, OCR-unavailable handling, and bilingual/motion/accessibility checks.
  - `python -m unittest test_layers_reorder` — Layers panel drag-and-drop Z-stack reordering: `ReorderZIndexCommand`/`ReorderPipItemsCommand` undo/redo, `_BranchlessTree` drag-compatibility rules, and the `MainWindow._on_layers_reorder_requested` integration.
- `TextItem.font_size_pt` / `Project.label_font_size` are **not** typographic points: the canvas and exporters scale a 24-unit reference box in mm (`ImageExporter._draw_text`), so one unit is ~1.8 mm of glyph box. Compact pre-loaded tutorial projects use small values (2, not 12); `first_figure` must instead retain normal new-project defaults. Tests should measure the rendered mm box rather than converting pt→mm.
- `image_proxy.image_format_name()` is the single source for the format shown in the Layers badge (`_ROLE_META` on leaf rows), the Inspector's Source Format row, and the status bar. Keep the Inspector caption short and put explanations in its tooltip — the form column is narrow and clips long text.
- The Layers panel (`src/app/layers_panel.py`) has two shapes. In grid mode it groups cells by row/column — a stable structural identity kept across swaps, unrelated to draw order — and cells are *not* draggable: z_index is meaningless while cells can't overlap (the row items carry no drag/drop flags and `MainWindow._on_layers_reorder_requested` ignores stray cell reorders). In freeform mode (`project.layout_mode == 'freeform'`, detected by `refresh()` → `tree.cells_reorderable`) it switches to a Photoshop-style flat layer list that *is* the z-stack: top row = frontmost (sort key `(z_index, creation index)` descending — creation order is the canvas's tie-break for equal zValues), no row headers, and PiP children shown reversed so they read front-to-back like their parents. Drag mechanics are Photoshop-like: the pointer's vertical half inside a row picks the boundary above/below it, `_BranchlessTree.paintEvent` draws an accent insertion line at that boundary (Qt's own drop indicator is disabled), hovering another cell's expanded inset rows maps to "behind that cell", and empty space below the list means the back of the stack. A drop emits `reorder_requested(dragged_id, target_id, place_above)` where place_above means "in front of the target" — never a reparent — for `MainWindow._on_layers_reorder_requested` to turn into `ReorderZIndexCommand` (renumbers every leaf cell's `z_index` to its rank — compact and deterministic, unlike `ZIndexChangeCommand`'s raw ±1 used by Bring to Front/Send to Back, which both remain) or `ReorderPipItemsCommand` (reorders `cell.pip_items`; list order *is* the PiP stack, last = frontmost). Drops that would land the cell on the stack slot it already occupies are skipped so undo history stays clean. PiP insets stay draggable in both modes — they overlap their host cell regardless of layout. A small "Z±n" chip (`_ROLE_ZIDX`) only appears on a grid-mode cell row once its `z_index` differs from the default 0 (in freeform the row's position already *is* its rank, so the chip is suppressed there).
- Guided tutorials live in `src/app/tutorials.py`: seven lessons keyed `first_figure`, `text_sizes`, `arrange_panels`, `labels_titles`, `publication`, `insets_scale_bars`, `size_groups`. Sample panels deliberately mix SVG/PNG/TIFF (Pillow writes the rasters, so no optional Qt image plugin is needed). Practice tabs stay open on exit (normal save/discard rules); switching tabs pauses guidance, and replacing/removing the practice layout stops it. Synthetic sample assets are generated locally under `QStandardPaths.AppLocalDataLocation/tutorial-samples-v2`, not temporary extraction directories, so saved plain projects retain working references. Tutorial highlights are child widgets, never scene/model items. Steps that target an Inspector field auto-expand its `CollapsibleSection` when the section is shown-but-folded (all sections start folded); a hidden section means the selection is wrong and is left alone. Steps that compare before/after state (freeform reposition, shared-label rename, PiP resize) capture their baseline lazily on first `ready()` evaluation so manual user actions count the same as the guided button.
- `arrange_panels` adds `crop` (right-click → Crop → aspect preset, mirrored by the guided action calling `MainWindow._ctx_crop_to_aspect` directly) and `fit_mode` (Inspector's `fit_mode_combo` + the 3×3 alignment grid, both already inside `cell_group`'s form) between `swap` and `freeform`. A test that crops to a square preset must wait for `image_proxy.get_pixmap()` to finish its async load first — the helper falls back to a 1:1 assumption when the pixmap isn't cached yet, which is a no-op for a square crop and would otherwise make the test flaky.
- `size_groups` reuses the same one-row-of-three pre-loaded practice project as `arrange_panels`/`labels_titles`/`publication`. `insets_scale_bars` instead gets its own dark-background `_sample_micrograph()` mocks (`make_samples()['insets_scale_bars']`, files `micrograph-*.svg`): `PiPItem.scale_bar_enabled` and the cell-level scale bar both default to white (`scale_bar_color`), so a white-background chart sample — or a letterboxed margin around any sample, light or dark — would make the bar invisible; `TutorialController.start()` runs `AutoLayoutCommand(project).redo()` on this lesson's project (synchronously, before the tab exists) to size each column to its image's aspect ratio and eliminate that margin. `AutoLayout.optimize_layout` reads image dimensions straight from disk (`QSvgRenderer`/PIL), not the async `image_proxy` cache, so this is safe to call immediately after assigning `cell.image_path` — contrast with `arrange_panels`'s `crop` step, whose test must wait for `image_proxy.get_pixmap()`'s cache instead. PiP insets are only user-creatable in the real UI by dragging an image onto an already-filled cell (`MainWindow._on_pip_image_dropped` → `AddPiPItemCommand`, `pip_type="external"`); `pip_type="zoom"` exists in the data model and agent tools (`pip_add`) but has no manual GUI trigger, so the lesson only teaches "external" insets. The guided `add_pip` action uses `tutorials.pip_icon_path()` (a bold single shape, `pip-icon.svg`) rather than any of the line-chart panel samples, which turn into an unreadable smudge shrunk to inset size. `PiPItem.border_color` defaults to `"#000000"` (was `"#FFFFFF"`) since a white border on a light panel background used to be nearly invisible; update the Inspector fallback in `_populate_pip_section` (`data.get("border_color", ...)`) to match if it ever changes again. `PiPItem.y` defaults to `0.05`, not `0.62` — the default inset sits top-right (`x=0.62` for a 5% right margin, `y=0.05` for a 5% top margin; `w=h=0.33`), not bottom-right; keep `agent/tools.py::pip_add`'s `y` default in sync since it mirrors this. Selecting a PiP for the `resize_inset` step needs `CellItem.select_pip(pip_id, resize=True)` *and* `item.setSelected(True)` — the existing `select_cell` action was hardened to call `item.deselect_pip()` first, otherwise a stale `_selected_pip_id` from an earlier step keeps routing `MainWindow._on_selection_changed()` to the PiP branch (and thus the wrong `scale_bar_enabled` — cell vs. PiP share the same Inspector checkbox) even after the cell is reselected. Size Groups: `size_group_pinned_w`/`size_group_pinned_h` live inside `cell_group`'s own form (not a separate `CollapsibleSection`), so the `select_cell` action already reveals them; creating/joining a group needs an actual scene selection first (`TutorialController._select_cells(...)`) since `MainWindow._on_size_group_create_from_selection`/`_on_size_group_add_to_existing` both read `self._selected_leaf_cells()`.
- `first_figure` calls `MainWindow._on_new_tab()` (the same path as File → New) so every project default matches, including page dimensions, margins, gap, DPI, fonts, label sizes, and project name. Only the tab's `tutorial_title` and tutorial save/exit lifecycle differ; do not apply the compact pre-loaded lessons' project overrides. `test_first_figure_matches_all_normal_new_project_defaults` compares serialized projects excluding generated cell IDs. Its own `delete_row`/`add_cell` steps teach getting from there to one row of three panels (delete the second row via `DeleteRowCommand`, then grow the row with `InsertCellCommand`) before `load` assigns the three sample images. Every other lesson still starts with its row of three panels pre-loaded, since they teach layout/labels/export, not import. Because `first_figure` deliberately shrinks and regrows `project.cells` as part of the lesson, `TutorialController.valid()` skips its usual "cell id set is unchanged" check for that lesson (the practice-project identity check is enough); don't reintroduce a strict id comparison there or `refresh()` will call `stop()` the moment the row is deleted.
- GUI tests need `QT_QPA_PLATFORM=offscreen`; Qt finds no system fonts offscreen, so tests load
  `%WINDIR%\Fonts\arial.ttf` explicitly when text rendering matters.
- Byte-compile check: `python -m compileall -q src main.py cli_main.py`.

## Project compatibility
- `src/model/migrations.py::PROJECT_SCHEMA_VERSION` is the project-data revision, independent of `APP_VERSION`.
- `schema_version` is written by `Project.to_dict()`; `file_version` records the writing application.
- All `Project.from_dict()` calls validate/migrate copied input. Bundle unpack also validates the project before extracting assets; ZIP/container safety gates remain separate.
- Missing `schema_version` means legacy schema 0. Migration 0→1 preserves explicit values and freezes legacy project defaults; absent raster OCR character boxes remain empty, without running OCR on load.
- Unsupported future schemas and newer app-only legacy files raise actionable errors. A newer writer using a supported explicit schema is allowed.
- Future incompatible changes must increment `PROJECT_SCHEMA_VERSION` and register each source revision in `SCHEMA_MIGRATIONS`; never just relabel old data. Add compatibility fixtures for renamed fields, default changes, and rendering semantics.
- Loading does not rewrite the source. Plain project saves and bundle saves use atomic replacement. Removed nested layouts without an image fallback are rejected rather than silently losing content.

## Label styling
- Every control in the Selected-Text panel (font, size, weight, colour) edits **only the selected label**; `apply_style_to_group` / `MainWindow._on_apply_style_to_group` is the one explicit way to restyle a group. Font/size/weight edits on a cell label also set `style_locked=True`, otherwise the tier-wide sync would silently revert them.
- Apply-to-all writes the project-level tier defaults (`label_*` / `title_label_*` / `corner_label_*`) **and** the members, and clears their locks, in one undo macro — so new labels match and the sync stops fighting the change. "All" means the selected label's own tier; corner labels are a separate group.
- Both `_refresh_and_sync_labels` and `_refresh_and_sync_corner_labels` skip `style_locked` items. `python -m unittest test_label_style` covers per-label isolation, locking, tier separation, undo granularity, and new-label defaults.

## Text size matching architecture
- Text groups (`Project.svg_text_groups`, `SvgTextGroup.font_size_pt`) are **points in the final figure**.
- `src/utils/panel_scale.py::panel_mm_per_unit` is the single source of truth for how many mm one image
  unit covers (fit/crop/rotation/layout); both SVG and raster pipelines divide by it.
- SVG: `svg_text_utils.get_svg_override_bytes_for_cell`; raster: `raster_text_utils.build_raster_override_spec`
  (+ `apply_raster_text_overrides`). Exporters go through `src/utils/text_overrides.overrides_for_cell`.
- Canvas: `CanvasScene.refresh_layout` puts both overrides in the per-cell fingerprint and passes them to
  `CellItem.update_data` → `ImageProxy.get_pixmap(..., svg_override_bytes, raster_override)` which caches per
  (path, content-hash), so the same file can render differently in different panels.
- Group overrides are written into the SVG in **user units** (`font-size:<n>px`, 1 px = 1 user unit) via `svg_mm_per_unit`, never in `pt`: QtSvg resolves `pt` at ~1.24 px/pt, not the `96/72` the page maths assumes, which rendered synced SVG text ~7% small and de-synced it from raster panels. `_set_font_size`/`_walk_normalize`/`_apply_group_font_sizes` take a `unit`; per-cell `svg_normalize_text` still writes `pt` (changing it would resize existing figures).
- `raster_text_utils.ink_ratio_for_text()` converts a label's ink-box height to an em. The ratio depends on the characters present (x-height 0.54, cap 0.72, ascender 0.73, +0.205 for descenders, 0.94 for CJK); the old single 0.72 constant biased the estimate by up to 30% ("Response", "Time (s)", CJK) and that error landed directly on the group scale.
- The contract both pipelines can hit exactly is the **em size on the page**. Residual differences in glyph *ink* are rasteriser-dependent (QtSvg hints vector text, so its ink runs a few percent shorter than an equivalent raster panel) and are not a code defect. `python -m unittest test_text_size_sync` asserts the exact em for both pipelines, tight raster-to-raster convergence, and a documented end-to-end bound.
- OCR backends live in `src/utils/raster_text_ocr.py`; selection is in Preferences → Text Detection
  (`ocr_backend` / `ocr_command` QSettings). Default and shipped backend: `rapidocr` (+ `onnxruntime`).
- Raster safety checks (`analyze_region`, `raster_text_utils.py`) judge a box's *own interior* only:
  background = dominant colour (robust to mixed-height glyphs touching the box edge), "touching" =
  foreground continuing from just inside to just outside an edge (real external object, not the
  label's own ink). `_classify_text_pixels` additionally splits interior foreground into connected
  components and keeps only ones reaching the text line's shared baseline — anything else (e.g. a
  diagram pointer sitting in the dead space a box picks up above short letters when the same line
  has tall ones) is excluded from extraction/scaling and left un-erased on the canvas
  (`RasterTextRegion.foreign_excluded`). Floating blobs that ARE text ("-", i-dots, accents, ":") are
  rescued using the OCR's per-character boxes as the judge (`RasterTextRegion.chars`, filled by every
  backend that can: RapidOCR word boxes, Tesseract `image_to_boxes`, command JSON `chars`): a blob under
  a character in `_FLOATING_CHARS` / with a combining mark / CJK is text; under a plain letter it's
  foreign. With no char info, geometry falls back to x-height band + centred-diacritic rules.
